# krema User QA Checklist

This is the list for checking that each feature behaves as intended when a user uses krema. Implementation-level checks (whether an interface is registered, whether a model is populated) are not included. Every item is written only in terms of actions the user performs directly and results the user sees.

Whether each item can be automated with the frame test harness in `tests/ci/` is also marked per item. This is used as the basis for deciding implementation order after approval.

## Automation tags

| Tag | Meaning |
|---|---|
| `AUTO` | Runnable as-is with the current harness |
| `AUTO-REQ` | Verifies only up to the values the client requested/computed. Cannot confirm whether the compositor actually drew it at that position on screen |
| `FIXTURE` | Uses the harness, but needs additional setup. What is needed is written per item |
| `MANUAL` | Not possible in a container. A person must verify on a real Plasma desktop |

Why `AUTO-REQ` exists separately: the verified capture path is the client-side `grabWindow()`, and that shows only the pixels inside the window. Compositor screenshots (`org.kde.KWin.ScreenShot2`) all fail in a container without `/dev/dri`. So "is the dock attached to the left edge of the screen with an 8px gap" can only be confirmed up to the requested anchor and margin values.

## VIS — Dock Display and Placement

### Visibility & Display

#### QA-VIS-001: Bottom Edge default placement and horizontal layout
- **User action**: Set Settings > General > dock position (`Edge`) to `1` (Bottom, default) and check the dock.
- **Expected**: The dock is placed at the bottom center of the screen, and pinned launchers and running app icons are aligned horizontally from left to right (`Flow.LeftToRight`). Panel height is computed as `IconSize` (default 48px) + panel padding (`16px`) + floating margin (`8px`).
- **Failure symptom**: The dock sits on an edge other than the bottom of the screen, is aligned vertically, or the panel drifts somewhere other than the screen center.
- **Evidence**: `src/config/krema.kcfg:47-50`, `src/platform/waylanddockplatform.cpp:168`, `src/qml/main.qml:627-633,703`
- **Priority**: P0
- **Automation**: `AUTO-REQ` — Verifies the values the client requests and computes (LayerShellQt anchors/margins, QQuickWindow geometry, Flow direction, panel width/height axes). Whether the compositor actually placed it at that position on screen is not verified by the current harness.

#### QA-VIS-002: Top Edge placement and horizontal layout switch
- **User action**: Change the dock position (`Edge`) to `0` (Top) in settings.
- **Expected**: The dock immediately moves to the top center of the screen, and icons remain aligned horizontally from left to right (`Flow.LeftToRight`).
- **Failure symptom**: The dock remains at the bottom after the setting change, or a Y coordinate calculation error for the top panel position pushes it off screen.
- **Evidence**: `src/config/krema.kcfg:47-50`, `src/platform/waylanddockplatform.cpp:163`, `src/qml/main.qml:643,703`
- **Priority**: P1
- **Automation**: `AUTO-REQ` — Verifies the values the client requests and computes (LayerShellQt anchors/margins, QQuickWindow geometry, Flow direction, panel width/height axes). Whether the compositor actually placed it at that position on screen is not verified by the current harness.
